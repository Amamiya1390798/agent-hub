# 检查方式

在仓库根目录运行 `sh tests/smoke.sh`。它只使用 Python 标准库和 Node 自带模块，不联网、不调用模型、不读取账号凭据。

- Python 3.9 语法检查及命令行帮助。
- 后端：实时输出、输入管道、超时子进程、停止状态、线程上下文、并发状态、依赖校验、方案存档、多轮追问、额度解析、登录启动失败、续聊命令转义、图片缺失、换模型后的历史后备统计。
- HTTP：在仓库内临时 HUB_HOME 和随机空闲端口启动面板，检查 state、submit、config、令牌、Host、窗口计数、图片类型，以及模拟后端提交（包括提交编号回传）和真实子进程停止。退出时清理临时实例；不使用 8765。
- 前端：Node 从 ui.html 抽取实际 Markdown 函数，检查标题、代码、引用、列表、表格、链接及转义；运行实际事件处理器，检查重新执行的上下文和出错恢复、慢响应与乱序轮询、并发任务下准确选中本次提交、历史首选模型标记。

`sh tests/live.sh` **会消耗少量模型额度**，不属于 smoke。它依次对 Gemini Flash、Codex、DeepSeek 各发一次“收到”，每次限时 60 秒，不调用 Claude、不尝试后备、不生成图片。结果写入 tests/live-results.json。它复用官方客户端的现有登录；没有登录或该模型不可用时会失败，不会修改账号或配置。

原始会话编号由真实调用结果取得。Codex 的终端续聊另作人工终端验收：`codex resume 会话编号` 应显示原来的提问和答复，检查后 `/exit` 退出，不需要额外发模型请求。

阶段 3：`node tests/test_ui_layout.js` 在原生 Node VM 中执行真实界面函数，检查团队卡片折叠与状态保留、四组设置、三步引导、多人分工计数与依赖、运行中的实际模型，以及仅出方案的显示。`test_api.py` 还会从随机端口临时服务读取实际页面，用 `node --check` 检查替换令牌后的脚本。它们不等同于浏览器截图或 WKWebView 真机验收。
